## 宿題

- 取り組んだレベル：発展
- 実行環境：Colab ではなく手元の Mac（Apple M3、16GB、MPS、32bit）。モデル・revision・LoRA 設定（r=16、alpha=32、lr=2e-4、バッチ 4×累積 2）・貪欲生成はノートブックと同じ。版は torch 2.11.0 / transformers 5.18.0 / peft 0.21.1 / trl 1.14.2。`max_new_tokens` は定義文が切れないよう 200 にした
- 変えた設定やデータ：
  - Run A：`scripts/make_sft_dataset.py` の出力そのまま（58 語 × 2 テンプレート = 116 件）。5 エポック（75 ステップ）
  - Run B：スクリプトに `--aliases`（3 文字以上の別名でも質問を作る）と `--unknown`（用語集に無い 8 語に「用語集に記載がありません。確認が必要です」と答える）を足した 239 件。5 エポック（150 ステップ）
  - 入力は質問文だけ（system なし）。学習データと同じ形
- 評価：22 問を自分で作った（`lectures/02/homework/glossary_sft.py` の `EVAL`）。答えに含まれるべき語句で自動判定する
  - seen 8 問：用語集の語を学習と同じテンプレートで聞く。講座固有の語（既定モデル、宿題の3レベル、lecNN-start タグ、Pi など）を多めにした
  - paraphrase 8 問：学習に無い言い回し・別名・逆引き（「LLM がもっともらしい嘘をつく現象を何と呼びますか」）
  - unknown 6 問：用語集に無い語（RAG、知識蒸留、RLHF、ベクトルデータベース、Mixture of Experts、プロンプトインジェクション）。一般知識として正しいかは自動判定が粗いので手で判定した
  - 用語集検索との比較として、`app/tools.py` の `search_glossary(質問文)` の結果をプロンプトに添える条件（+search）も測った
- 結果：

  | 条件 | seen | paraphrase | 定義文との一致度 seen / para | unknown 正しい説明（手判定） | unknown「記載なし」 |
  |---|---|---|---|---|---|
  | 学習前 | 0/8 | 0/8 | 0.06 / 0.09 | 4/6 | 0/6 |
  | 学習前 + 検索 | 5/8 | 3/8 | 0.57 / 0.31 | 2/6 | 2/6 |
  | Run A 学習後 | 3/8 | 1/8 | 0.48 / 0.25 | 2/6 | 0/6 |
  | Run A 学習後 + 検索 | 3/8 | 1/8 | 0.74 / 0.28 | 1/6 | 1/6 |
  | Run B 学習後 | **8/8** | 3/8 | 1.00 / 0.45 | 0/6 | 2/6 |
  | Run B 学習後 + 検索 | 5/8 | 2/8 | 0.86 / 0.41 | 0/6 | 0/6 |

  一致度は `difflib` の文字単位の比率。学習時間は Run A 2763 秒（最終 loss 0.41）、Run B 4316 秒（最終 loss 0.11）。生データは `lectures/02/homework/results/`

  - 学習前は「ハルシネーション」を物理学の用語、「Pi」を円周率、「AIE2026 の標準モデル」を BERT と答えた。講座固有の語は 1 問も当たらなかった
  - Run B の学習後は seen 8 問すべてで定義文を一字一句再現した（一致度 1.00）。Run A は loss 0.41 で止まり、LoRA と既定モデルは完全に再現したが、宿題の3レベルや Pi は講座の文体で作り話をした
  - 言い換えには弱かった。Run B の paraphrase で当たった 3 問のうち 2 問（Low-Rank Adaptation、Pi coding agent）は `--aliases` で別名を学習に入れた語で、純粋に新しい言い回しで当たったのは「標準的に使うモデル」の 1 問だけだった。逆引きの「もっともらしい嘘をつく現象を何と呼ぶか」は全条件で外れた
  - 学習後は用語集に無い語も講座の用語のように説明した。Run A は「知識蒸留」を「AIE2026 の宿題・演習の進め方」と答えた。Run B は RLHF に SFT の定義、プロンプトインジェクションに Human-in-the-loop の定義をそのまま返した。学習前に 4/6 正しく説明できた一般知識が、Run B では 0/6 になった
  - `--unknown` で「記載がありません」の例を 16 件入れても、評価用の未知語 6 問で断ったのは 2 問だった。断り方は学習したが、どの語を知らないかの判断は身につかなかった
  - 検索は、ヒットすれば学習なしで 5/8 当たった。外れた原因は検索側で、「Pi」は 2 文字で部分一致の対象外、逆引きの質問 4 問には用語名が含まれないので何も返らなかった。ヒットしないとき、学習前のモデルは「見つかりませんでした」と答えたが、学習後のモデルは作り話をした
  - 学習後のモデルに検索結果を渡すと、seen は Run B で 8/8 → 5/8 に下がった。学習した文を優先し、渡した検索結果を読み替える出力があった
- ファインチューニングが向く場面・向かない場面についての考察：
  - 用語集を学習させるメリット：プロンプトに検索結果を入れなくても答えられるので、入力が短く、検索の仕組みもいらない。答えの文体や長さが用語集の定義文に揃う。Run B の seen 8/8 のように、学習データと同じ聞き方なら定義を正確に返せる
  - デメリット：
    - 学習した聞き方から外れると当たらない（paraphrase 3/8）。検索は質問に語が含まれていれば聞き方に依存しない
    - 知らない語にも講座の文体で断定的に答え、近い語の定義を取り違える。一般知識も失われた（unknown の正しい説明 4/6 → 0/6）。検索なら「見つかりませんでした」と分かる
    - 用語集を更新するたびに学習し直す必要がある。今回の環境では Run B の学習に 72 分かかった。検索なら JSON を書き換えるだけで反映される
    - 何を根拠に答えたかが出力から分からない。検索なら返した項目を示せる
  - 結論：用語の定義のように正確さと更新が必要な知識は、検索で渡すほうが向いていると考える。ファインチューニングは第2回の演習の JSON 形式のような、出力の形や振る舞いをそろえる用途に向く。今回の結果では、学習で知識を入れると、知らない語の扱いと言い換えへの対応が悪くなった
  - 検索側の改善点も見えた。2 文字の語や逆引きに対応できないので、別名の追加や定義文を対象にした検索（埋め込みなど）が必要になる。学習と組み合わせるなら、学習では「検索結果だけを根拠に答え、無ければ記載なしと言う」振る舞いを教え、知識は検索で渡す形がよいと考えるが、試していない
