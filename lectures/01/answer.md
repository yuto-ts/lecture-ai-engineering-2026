## 宿題

- 取り組んだレベル：発展
- 使ったモデル：Gemini（無料枠）`gemini-3.5-flash-lite` / `gemini-3.1-flash-lite` / `gemini-3.5-flash`、Claude（有料）`claude-haiku-5-5` / `claude-sonnet-5-5` / `claude-opus-5-5`、OpenAI（有料）`gpt-5.4-nano` / `gpt-5.4-mini` / `gpt-5.5`。設定は各社の既定のまま。`gemini-2.5-flash` は新規ユーザーには 404 で使えなかった
- やったこと：
  - 計測スクリプト `app/bench.py` を作った。ストリーミングで呼び、最初の本文が届くまで（TTFT）と全体の秒数、入力・出力・思考トークン数を CSV に記録する。レート制限の上限値も、Claude と OpenAI はレスポンスヘッダーから、Gemini は 429 のエラー本文から記録する
  - 長さの違う 4 つの質問（一文で答える / 普通 / 講座に固有 / 長い説明）を、9 モデル × 3 回 = 108 回聞いた。別に `gemini-3.5-flash-lite` へ待ちなしで 30 回連続して送った
  - 生データは `lectures/01/results/`、再現は `uv run --group bench --env-file .env python -m app.bench --models ...`
- 結果：

  数値は中央値（TTFT と思考は全質問、ほかは該当の質問）。tok/s は（出力 + 思考）÷ 全体の秒数。gemini-3.5-flash の long は 1 回しか成功していない。費用はトークン数 × 単価の推定で、合計約 $1.36

  - 全体の時間はほぼ回答の長さで決まった。long の回答はモデルで 7 倍違い（898〜6309 トークン）、opus は約 62 秒かかった
  - TTFT が長いのは思考トークンが多いモデルだった。gemini-3.5-flash は「一文で」と頼んでも約 430 トークン考え、TTFT は 3.7 秒だった
  - 失敗は Gemini 無料枠の 6 回だけ。503（混雑）が 5 回、1 日の上限の 429 が 1 回。Claude と OpenAI は 72 回すべて成功した
  - レート制限の上限（1 分あたり）：Gemini 無料枠は gemini-3.5-flash-lite で 15 リクエスト（連続送信では 18 回目から 429）、gemini-3.5-flash は 1 日 20 リクエスト。Claude は 10,000 リクエスト、OpenAI は 5,000 リクエスト
- 気づき・疑問：
  - 無料枠で当たるのはトークン数ではなくリクエスト数の上限だった。入力は 1 回 7〜50 トークンしかない
  - エージェントが 1 質問で LLM を 4 回呼ぶとすると、gemini-3.5-flash-lite は 1 分に 3 質問強、gemini-3.5-flash は 1 日 5 質問しかできない。無料枠では既定の flash-lite のまま使うのがよいと考える
  - 有料 API の上限は今回のペースより 3 桁以上大きく、一度も当たらなかった
  - 速さを比べるときは TTFT と tok/s を分けて見る必要がある。全体の秒数だけだと、短く答えるモデルが速く見える
  - 思考トークンの課金上の扱いは確かめていない（費用は出力として計算した）
